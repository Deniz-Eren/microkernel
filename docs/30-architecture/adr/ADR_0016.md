# ADR_0016 — Ring 3 VFS Server with Read-Only Bootfs and Dynamic Tmpfs

```{adr} Ring 3 VFS server with read-only bootfs and dynamic tmpfs
:id: ADR_0016
:status: accepted

## Context

For `SWR_IPC_0007`, the system must give POSIX.1-2024 file operations (`open`,
`openat`, `lseek`, `ftruncate`, `stat`, `fstat`, `readdir`, `mkdir`, `unlink`,
`chdir`, `getcwd`) on read-only `bootfs` and writable `tmpfs` without filesystem
code in Ring 0.

## Decision

- `libc/include/sys/fd.h` adds `FD_KIND_VFS` (`3`), and `kernel/core/proc.c`
  sends `PULSE_CODE_FD_CLOSE` on `O_CLOEXEC` and process exit.
- The kernel maps the Multiboot2 `boot.tar` module read-only (`VMM_USER |
  VMM_PRESENT | VMM_NX`) into `vfsserv` at `BOOTFS_USER_VA` (`0x11000000`) and
  increases PMM frame refcounts.
- `servers/vfsserv/main.c` (`COMP_IPC_0008`) records `/dev/vfs` in `sysproc`. It
  gives `boot.tar` entries in read-only `/boot` (`EROFS` on writes). It also
  gives writable `tmpfs` in `/` and `/tmp` with `mmap` buffers and deferred
  release of unlinked open files.
- `libc/include/sys/vfs.h` (`ICD_IPC_0007`) sets `/dev/vfs` IPC messages in
  `IPC_MSG_MAX` (`512` bytes).
- The project adds `<sys/stat.h>` (`ICD_IPC_0008`), `<dirent.h>`
  (`ICD_IPC_0009`), and `libc/src/vfs.c` (`COMP_IPC_0009`). `open`, `openat`,
  and `creat` stay cancellation points, and async-signal-safe VFS calls do not
  lock heap mutexes.

## Rejected alternatives

- A VFS and `tmpfs` layer in Ring 0, which does not obey the microkernel
  boundary in `ADR_0003`.
- A Ring 3 heap copy of `boot.tar`, which wastes RAM compared with read-only
  page tables.

## Results

- Ring 3 executables and services (`SHM`, command shell `sh`) can open, `lseek`,
  `ftruncate`, `stat`, read, and change files through standard headers.
- `SWR_IPC_0007` is active, and `vfstest` (`VER_IPC_0005`) and all four CTest
  POSIX.1-2024 compatibility checks do tests for it.
```
