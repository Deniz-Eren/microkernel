# ADR_0016 — Ring 3 VFS Server with Read-Only Bootfs and Dynamic Tmpfs

```{adr} Ring 3 VFS server with read-only bootfs and dynamic tmpfs
:id: ADR_0016
:status: accepted

## Context

`SWR_IPC_0007` requires POSIX.1-2024 file operations (`open`, `openat`, `lseek`,
`ftruncate`, `stat`, `fstat`, `readdir`, `mkdir`, `unlink`, `chdir`, `getcwd`)
over read-only `bootfs` and writable `tmpfs` without moving filesystem logic
into Ring 0.

## Decision

- Add `FD_KIND_VFS` (`3`) in `libc/include/sys/fd.h` and send
  `PULSE_CODE_FD_CLOSE` from `kernel/core/proc.c` on `O_CLOEXEC` and process
  exit.
- Map the Multiboot2 `boot.tar` module read-only (`VMM_USER | VMM_PRESENT |
  VMM_NX`) into `vfsserv` at `BOOTFS_USER_VA` (`0x11000000`) with PMM frame
  refcounts incremented.
- Build `servers/vfsserv/main.c` (`COMP_IPC_0008`) registering `/dev/vfs`.
  Expose `boot.tar` entries under read-only `/boot` (`EROFS` on mutation). Serve
  writable `tmpfs` under `/` and `/tmp` with dynamic `mmap`-backed buffers and
  deferred reclamation of unlinked open files.
- Define `/dev/vfs` IPC messages in `libc/include/sys/vfs.h` (`ICD_IPC_0007`)
  within `IPC_MSG_MAX` (`512` bytes).
- Add `<sys/stat.h>` (`ICD_IPC_0008`), `<dirent.h>` (`ICD_IPC_0009`), and
  `libc/src/vfs.c` (`COMP_IPC_0009`). Keep `open`, `openat`, and `creat` as
  cancellation points and keep async-signal-safe VFS calls free of heap locks.

## Rejected alternatives

- Putting a VFS and `tmpfs` layer inside Ring 0 (violates the microkernel
  boundary in `ADR_0003`).
- Copying `boot.tar` into Ring 3 heap memory (wastes RAM compared to read-only
  page mapping).

## Consequences

- Ring 3 applications and future services (`SHM`, command shell `sh`) can open,
  seek, truncate, stat, enumerate, and mutate files through standard headers.
- `SWR_IPC_0007` is active and verified by `vfstest` (`VER_IPC_0005`) and all
  four CTest POSIX.1-2024 compatibility gates.
```
