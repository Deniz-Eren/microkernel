# ADR_0059 — Shared libc.so Conventions for Dynamic Executables

```{adr} Shared libc.so conventions for dynamic executables
:id: ADR_0059
:status: accepted

Ship a position-independent shared `libc.so` with soname `libc.so` beside static
`libc.a`. Link dynamic executables against it with a `FILEHDR PHDRS` linker
script. The runtime `dlopen`, `dlsym`, `dlclose`, and `dladdr` calls from shared
`libc.so` delegate to the `/boot/ld.so` interpreter through weak `ldso_*`
exports.
```

## Context

TSK_0061 delivered the kernel `PT_INTERP` handoff and the freestanding Ring 3
dynamic linker `/boot/ld.so`. Dynamic executables still linked a static `libc.a`
copy into every image. Their runtime `dlopen` calls used the built-in loader
inside the executable. That loader was not the interpreter that had loaded the
process. TSK_0062 adds shared `libc.so` so Ring 3 libraries and executables
share one C library instance.


The C library keeps per-thread state (errno, dlerror) in a custom `FS.base` TCB.
It contains no ELF `__thread` TLS. This removes the hardest part of building a
shared libc for this kernel. The interpreter already resolves symbols in a
global scope and supports reference-counted `dlclose`.

## Decision

1. **Image base 0 PIE convention:** dynamic executables link with
   `--pic-executable -T user-dyn.ld`, a `FILEHDR PHDRS` script whose first LOAD
   segment holds the ELF and program headers at image base 0. The kernel maps
   the image at `ELF_DYN_BASE` (`0x400000`). It computes the load bias from the
   mapped base. No fixed non-zero base is baked into the image.
2. **Constructor split between ld.so and `__libc_start_main`:** a dynamic
   executable with `DT_NEEDED libc.so` runs its `DT_INIT` and `DT_INIT_ARRAY`
   inside `__libc_start_main` after libc TCB setup, which matches the static
   crt0 handoff. `/boot/ld.so` runs constructors for all loaded libraries and
   for freestanding dynamic executables without `libc.so`.
3. **No ELF TLS in `libc.so`:** the C library continues to keep errno, dlerror,
   and pthread state in the custom `FS.base` TCB. TLS relocations
   (`R_X86_64_DTPMOD64`, `TPOFF64`) stay unsupported in the interpreter and out
   of `libc.so`.
4. **Weak ldso delegation:** shared `libc.so` declares `ldso_dlopen`,
   `ldso_dlsym`, `ldso_dlclose`, and `ldso_dladdr` as weak externals. It
   delegates when they resolve. The built-in ET_DYN loader in libc stays the
   fallback for statically linked executables. Errors travel back through
   caller-provided buffers so `dlerror` remains thread-local in libc.
5. **Eager binding and global scope aliases:** the interpreter binds all symbols
   eagerly and inserts every object into the global scope.
   `RTLD_LAZY`/`RTLD_NOW` and `RTLD_LOCAL`/`RTLD_GLOBAL` are accepted as aliases
   of this behavior and do not select different binding.
6. **dlclose semantics:** runtime objects (`dlopen` after startup) unmap with
   finis when the last reference closes. Startup `DT_NEEDED` objects stay loaded
   for the process lifetime because the executable itself references them.
   `dlclose` on the main executable returns success.
7. **No loader locking:** the interpreter tables are not protected by a lock.
   Runtime loading is a single-threaded loader operation. A multi-threaded
   process must not call `dlopen` concurrently with exit paths that unmap
   objects.
8. **Coverage instrumentation stays in static `libc.a`:** the shared library
   carries no coverage hooks, matching the toolchain configuration for
   freestanding Ring 3 code.

## Rejected alternatives

- Linking dynamic executables against static `libc.a`: every image carried a
  private libc copy. `dlopen` used the built-in loader instead of `/boot/ld.so`.
  Shared libraries cannot resolve libc symbols.
- Giving shared `libc.so` ELF TLS support in the interpreter: TLS relocation
  support in `ld.so` is a large, separate milestone with no current consumer,
  because the libc uses the `FS.base` TCB everywhere.
- A fixed non-zero base in the linker script: it duplicates the kernel placement
  decision in user-space build files and breaks if the kernel moves
  `ELF_DYN_BASE`.
- Exporting the delegation through a versioned symbol interface: no consumer
  needs versioning yet, and weak symbols keep statically linked executables
  working with one code path.

## Consequences

- Ring 3 executables and libraries share one libc instance, and runtime `dlopen`
  from a dynamic executable exercises `/boot/ld.so` itself.
- The interpreter and libc share the error contract through caller buffers.
  `dlerror` strings are limited to the libc TLS buffer size.
- Adding ELF TLS to `libc.so` later requires interpreter TLS relocation support
  and a new ADR.
- `tests/dynlibctest` verifies stdio, malloc, pthreads, TLS errno, signals,
  fork/execve, and runtime `dlopen` through the shared libc in QEMU
  {need}`VER_LIBC_0033`.
