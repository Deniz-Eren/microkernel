# ADR_0059 — Shared libc.so Conventions for Dynamic Executables

```{adr} Shared libc.so conventions for dynamic executables
:id: ADR_0059
:status: accepted

The build includes a PIE shared `libc.so` with soname `libc.so` and static
`libc.a`. Dynamic executables link to `libc.so` with a `FILEHDR PHDRS` linker
script. Runtime `dlopen`, `dlsym`, `dlclose`, and `dladdr` calls from shared
`libc.so` delegate to the `/boot/ld.so` interpreter through weak `ldso_*`
exports.
```

## Context

`TSK_0061` added the kernel `PT_INTERP` handoff and the freestanding Ring 3
dynamic linker `/boot/ld.so`. Dynamic executables linked a static `libc.a` copy
into each image. Their runtime `dlopen` calls used the internal loader in the
executable, not the interpreter that loaded the process. `TSK_0062` adds shared
`libc.so`. Thus, Ring 3 libraries and executables use one C library instance.

The C library keeps thread-local state (`errno`, `dlerror`) in a custom
`FS.base` TCB and contains no ELF `__thread` TLS. This design removes the
hardest part of a shared `libc` for this kernel. The interpreter finds symbols
in a global scope and operates with use-counted `dlclose`.

## Decision

1. **Image base 0 PIE convention:** Dynamic executables link with
   `--pic-executable -T user-dyn.ld`, a `FILEHDR PHDRS` script with a first
   `LOAD` segment that keeps the ELF and program headers at image base 0. The
   kernel maps the image at `ELF_DYN_BASE` (`0x400000`) and calculates the load
   bias from the mapped base. The linker puts no fixed non-0 base in the image.
2. **Constructor division between `ld.so` and `__libc_start_main`:** A dynamic
   executable with `DT_NEEDED libc.so` calls its `DT_INIT` and `DT_INIT_ARRAY`
   in `__libc_start_main` after `libc` TCB initialization, in agreement with the
   static `crt0` handoff. `/boot/ld.so` calls constructors for all loaded
   libraries and for freestanding dynamic executables without `libc.so`.
3. **No ELF TLS in `libc.so`:** The C library keeps `errno`, `dlerror`, and
   `pthread` state in the custom `FS.base` TCB. TLS relocations
   (`R_X86_64_DTPMOD64`, `TPOFF64`) do not operate in the interpreter and stay
   out of `libc.so`.
4. **Weak `ldso` delegation:** Shared `libc.so` declares `ldso_dlopen`,
   `ldso_dlsym`, `ldso_dlclose`, and `ldso_dladdr` as weak externals and
   delegates when they resolve. The internal `ET_DYN` loader in `libc` stays the
   alternative for statically linked executables. Errors go back through
   caller-supplied buffers. Thus, `dlerror` stays thread-local in `libc`.
5. **Eager symbol resolution and global scope aliases:** The interpreter
   resolves all symbols eagerly and puts each object into the global scope. The
   interpreter accepts `RTLD_LAZY`, `RTLD_NOW`, `RTLD_LOCAL`, and `RTLD_GLOBAL`
   as aliases of this operation and does not select different symbol modes.
6. **`dlclose` rules:** Runtime objects (`dlopen` after startup) unmap with
   destructors when the last use count closes. Startup `DT_NEEDED` objects stay
   loaded for the process lifetime because the executable refers to them.
   `dlclose` on the primary executable gives `0`.
7. **No loader mutex:** The interpreter does not lock its tables. Runtime loader
   calls operate in one thread. A multi-thread process must not call `dlopen` at
   the same time as exit paths that unmap objects.
8. **Coverage instrumentation in static `libc.a`:** The shared library has no
   coverage calls, in agreement with the toolchain configuration for
   freestanding Ring 3 code.

## Rejected alternatives

- **Dynamic executables linked to static `libc.a`:** Each image kept a private
  `libc` copy. `dlopen` used the internal loader and not `/boot/ld.so`. Shared
  libraries cannot find `libc` symbols.
- **ELF TLS in `ld.so` for shared `libc.so`:** TLS relocations in `ld.so` are a
  large, isolated milestone with no active consumer because `libc` uses the
  `FS.base` TCB everywhere.
- **A fixed non-0 base in the linker script:** This alternative makes a second
  copy of the kernel placement decision in user-space build files and stops with
  an error if the kernel moves `ELF_DYN_BASE`.
- **Delegation through a versioned symbol interface:** No consumer must have
  symbol versions at this time, and weak symbols keep statically linked
  executables in operation with one code path.

## Results

- Ring 3 executables and libraries use one `libc` instance, and runtime `dlopen`
  from a dynamic executable does tests of `/boot/ld.so`.
- The interpreter and `libc` use the same error interface through caller
  buffers. The `libc` TLS buffer capacity limits `dlerror` strings.
- Subsequent ELF TLS in `libc.so` must have interpreter TLS relocations and a
  new ADR.
- `tests/dynlibctest` does tests of `stdio`, `malloc`, `pthreads`, TLS `errno`,
  signals, `fork`, `execve`, and runtime `dlopen` through the shared `libc` in
  QEMU {need}`VER_LIBC_0033`.
