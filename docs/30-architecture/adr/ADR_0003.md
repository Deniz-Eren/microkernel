# ADR_0003 — Align User Space to POSIX.1-2024 Base via Libc and Ring 3 Servers

```{adr} Align user space to POSIX.1-2024 Base via libc and Ring 3 servers
:id: ADR_0003
:status: accepted

## Context

`microkernel` keeps the Ring 0 kernel minimal while targeting IEEE Std
1003.1-2024 (Issue 8) Base conformance (`_POSIX_VERSION=202405L`). Today,
`libc/include/unistd.h` leaks `<sys/microkernel.h>`, `<errno.h>` is absent,
`<sys/signal.h>` uses non-POSIX `sigaction`/`kill` signatures, and
`sys_sigaction` does not reject `SIGKILL` or `SIGSTOP`.

## Decision

Implement POSIX.1-2024 Base semantics through three layers without inflating
Ring 0:

- Keep raw kernel syscalls isolated from `errno`, `FILE` locking, and
  cancellation state, returning negative error numbers in `RAX`.
- Enforce standalone header hygiene, thread-local `errno`, cancellation points,
  async-signal-safety, and mandatory Base interfaces (`pthread_*`, `sem_*`,
  clocks/timers, `mmap` family, `aio_*`) in `libc`.
- Implement descriptor I/O, pipes, polling, asynchronous I/O, and future XCU
  shell/utilities in Ring 3 user servers over kernel IPC channels, gating option
  groups (`SHM`, `SPN`, `ML`, `MLR`, `MSG`, `PS`) behind `_POSIX_*` macros.

## Rejected alternatives

- Moving POSIX filesystems, pipes, and AIO workers into the Ring 0 kernel.
- Exposing custom `microkernel` symbols unconditionally inside standard POSIX
  headers.

## Consequences

- Standard headers compile cleanly under `-D_POSIX_C_SOURCE=202405L` without
  exposing non-standard `SYS_*` macros.
- Existing milestone code migrates incrementally as each draft POSIX requirement
  transitions to `active` with automated verification.
```
