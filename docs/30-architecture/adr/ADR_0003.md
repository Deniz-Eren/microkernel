# ADR_0003 — POSIX.1-2024 Base User Space with libc and Ring 3 Servers

```{adr} POSIX.1-2024 Base user space with libc and Ring 3 servers
:id: ADR_0003
:status: accepted

## Context

`microkernel` keeps the Ring 0 kernel small and has the objective of
compatibility with interfaces from POSIX.1-2024 (IEEE Std 1003.1-2024 /
ISO/IEC/IEEE 9945:2026, `_POSIX_VERSION=202405L`). Before this decision,
`libc/include/unistd.h` included `<sys/microkernel.h>`, `<errno.h>` was missing,
`<sys/signal.h>` used non-POSIX `sigaction` and `kill` signatures, and
`sys_sigaction` did not reject `SIGKILL` or `SIGSTOP`.

## Decision

The project targets interfaces from POSIX.1-2024 Base through three layers and
keeps Ring 0 small:

- Kernel syscalls stay isolated from `errno`, `FILE` mutexes, and cancellation
  state, and give negative error numbers in `RAX`.
- `libc` keeps standalone headers clean and gives thread-local `errno`,
  cancellation points, async-signal-safe wrappers, and Base interfaces
  (`pthread_*`, `sem_*`, clocks, timers, `mmap`, `aio_*`).
- Ring 3 servers operate descriptor I/O, pipes, `ppoll`, AIO, and shell
  utilities through IPC channels. Option groups (`SHM`, `SPN`, `ML`, `MLR`,
  `MSG`, `PS`) stay behind `_POSIX_*` macros.

## Rejected alternatives

- POSIX filesystems, pipes, and AIO workers in the Ring 0 kernel.
- Custom `microkernel` symbols in standard POSIX headers.

## Results

- Standard headers compile without errors with `-D_POSIX_C_SOURCE=202405L` and
  do not show non-standard `SYS_*` macros.
- Milestone code moves step by step when each draft POSIX requirement changes to
  `active` with automatic tests.
```
