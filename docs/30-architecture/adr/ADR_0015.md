# ADR_0015 — Mmap-Backed Thread-Safe Slab and Large-Block Heap Allocator

```{adr} Mmap-backed thread-safe slab and large-block heap allocator
:id: ADR_0015
:status: accepted

## Context

`SWR_MEM_0006` requires `<stdlib.h>` heap allocation to back blocks with `mmap`,
reclaim memory through `free` and `munmap`, and synchronize concurrent threads.
The prior static 1 MiB bump arena in `libc/src/stdlib.c` never reclaimed memory
and added 1 MiB of `.bss` to each user binary.

## Decision

- Implement a dedicated allocator in `libc/src/malloc.c` (`COMP_MEM_0004`) and
  remove the static bump arena from `libc/src/stdlib.c`.
- Serve allocations of 32 KiB or more directly via page-aligned `mmap` and
  reclaim them immediately via `munmap` on `free` with no heap lock held.
- Serve smaller allocations from 64 KiB `mmap` slabs with 16-byte aligned blocks
  and first-fit splitting. Coalesce adjacent free blocks immediately and support
  in-place `realloc` growth or tail splitting.
- Cache at most one empty slab to avoid syscall thrashing and immediately
  `munmap` additional empty slabs back to the kernel PMM.
- Synchronize slab metadata with a `SYS_FUTEX` lock (`FUTEX_WAIT`/`FUTEX_WAKE`)
  and save/restore `errno` in `free` to obey POSIX.1-2024.
- Verify alignment, 20 MiB slab churn, 16 MiB large `munmap` reclamation,
  `realloc` boundary crossings, and 4-thread concurrency in
  `tests/heaptest/test_heap.c`.

## Rejected alternatives

- Keeping a static `.bss` arena with a free list (caps heap size and wastes
  physical RAM across every Ring 3 server).
- Using a raw spinlock across `mmap`/`munmap` syscalls (wastes CPU quanta under
  preemption).

## Consequences

- Ring 3 servers and applications reclaim physical memory on `free` and
  `realloc` and scale past 1 MiB within the 768 MiB user `mmap` window.
- Every Ring 3 ELF binary drops 1 MiB of static `.bss` overhead.
- `SWR_MEM_0006` is active and verified by `heaptest` (`VER_MEM_0003`) and CTest
  `posix.symbol_diff` and `posix.async_signal_safe`.
```
