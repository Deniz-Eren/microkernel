# ADR_0015 — Mmap-Backed Thread-Safe Slab and Large-Block Heap Allocator

```{adr} Mmap-backed thread-safe slab and large-block heap allocator
:id: ADR_0015
:status: accepted

## Context

For `SWR_MEM_0006`, `<stdlib.h>` heap allocation must use `mmap`, release memory
through `free` and `munmap`, and lock metadata for concurrent threads. The
previous static 1 MiB linear arena in `libc/src/stdlib.c` did not release memory
and added 1 MiB of `.bss` to each user executable.

## Decision

- `libc/src/malloc.c` (`COMP_MEM_0004`) adds a slab and large-block allocator
  and removes the static linear arena from `libc/src/stdlib.c`.
- Allocations of 32 KiB or more use page-aligned `mmap` and release immediately
  through `munmap` on `free` with no heap mutex locked.
- Smaller allocations use 64 KiB `mmap` slabs with 16-byte aligned blocks and
  first-fit division. The allocator merges adjacent free blocks immediately and
  can expand or divide blocks on `realloc`.
- The allocator keeps at most one empty slab to prevent frequent syscalls. It
  calls `munmap` immediately on more empty slabs to release frames to the kernel
  PMM.
- A `SYS_FUTEX` mutex (`FUTEX_WAIT` and `FUTEX_WAKE`) locks slab metadata, and
  `free` keeps `errno` unchanged to obey POSIX.1-2024.
- `tests/heaptest/test_heap.c` does tests of 16-byte aligned blocks, 20 MiB slab
  churn, 16 MiB large `munmap` release, `realloc` boundary changes, and 4-thread
  concurrency.

## Rejected alternatives

- A static `.bss` arena with a free table, which limits heap capacity and wastes
  physical RAM in each Ring 3 server.
- A raw spinlock across `mmap` and `munmap` syscalls, which wastes CPU time
  slices during preemption.

## Results

- Ring 3 servers and executables release physical memory on `free` and `realloc`
  and allocate more than 1 MiB in the 768 MiB user `mmap` window.
- Each Ring 3 ELF executable removes 1 MiB of static `.bss` memory.
- `SWR_MEM_0006` is active, and `heaptest` (`VER_MEM_0003`), CTest
  `posix.symbol_diff`, and `posix.async_signal_safe` do checks on it.
```
