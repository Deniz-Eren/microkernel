# ADR_0005 — Implement Lock-Free TID-Indexed Thread-Local errno

```{adr} Implement lock-free TID-indexed thread-local errno
:id: ADR_0005
:status: superseded

## Context

`SWR_LIBC_0003` requires `<errno.h>` to expose a thread-local `errno` lvalue
isolated across Ring 3 threads and async-signal-safe without heap allocation or
mutex locks. Before `TSK_0006`, the kernel did not program per-thread `FS.base`
TLS descriptors.

## Decision

Implement `__errno_location()` in `libc/src/errno.c` with a fixed 64-slot atomic
table keyed by kernel TID (`ThreadGetCtx(0, &ti)`). Each thread claims a slot
with `__atomic_compare_exchange_n`, starts with `errno == 0`, and never calls
`malloc` or acquires locks. Replace the primary storage with `FS`-relative TLS
when `pthread` TLS lands without changing the `<errno.h>` ABI.

## Rejected alternatives

- Using a single global `int errno` (races between concurrent Ring 3 threads).
- Adding kernel `FS.base` MSR management during `TSK_0001` before `pthread` work
  started.

## Consequences

- Concurrent Ring 3 threads gained isolated, async-signal-safe `errno` storage
  early without locks or heap allocation.
- `ADR_0010` later upgraded primary storage to O(1) `IA32_FS_BASE` TLS while
  keeping the lock-free TID table as a fallback.
```
