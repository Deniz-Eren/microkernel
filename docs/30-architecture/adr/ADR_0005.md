# ADR_0005 — Lock-Free TID-Indexed Thread-Local errno

```{adr} Lock-free TID-indexed thread-local errno
:id: ADR_0005
:status: superseded

## Context

For `SWR_LIBC_0003`, `<errno.h>` must give an async-signal-safe thread-local
`errno` isolated across Ring 3 threads without heap allocation or mutexes.
Initially, the kernel did not set `FS.base` TLS descriptors for each thread.

## Decision

`libc/src/errno.c` gives `__errno_location()` with a fixed 64-slot atomic table
that uses kernel TID entries (`ThreadGetCtx(0, &ti)`). Each thread claims a slot
with `__atomic_compare_exchange_n`, starts with `errno == 0`, and does not call
`malloc` or lock a mutex. `FS`-relative TLS replaces this primary table when
`pthread` TLS is active without an `<errno.h>` ABI change.

## Rejected alternatives

- One global `int errno`, which causes data races across concurrent Ring 3
  threads.
- Kernel `FS.base` MSR code before `pthread` work started.

## Results

- Concurrent Ring 3 threads got isolated, async-signal-safe `errno` storage
  without mutexes or heap allocation.
- `ADR_0010` subsequently changed primary storage to O(1) `IA32_FS_BASE` TLS and
  kept the lock-free TID table as an alternative.
```
