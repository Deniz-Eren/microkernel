# ADR_0019 — Buffered Stdio, Environment Mutation, execvp, and Core C17 Headers

```{adr} Buffered stdio, environment mutation, execvp, and core C17 headers
:id: ADR_0019
:status: accepted

## Context

`SWR_LIBC_0007` requires buffered `<stdio.h>` streams, `setenv` and `unsetenv`,
`execv` and `execvp`, and the core C17 and POSIX headers `<ctype.h>`,
`<assert.h>`, `<inttypes.h>`, `<strings.h>`, and `<limits.h>`. Previously,
`<stdio.h>` only supported unbuffered `stdout`/`stderr` writes and `<limits.h>`
came only from Clang's freestanding resource directory without POSIX limits.

## Decision

- Place `${SYSROOT_DIR}/usr/include` ahead of `${CLANG_RESOURCE_DIR}/include` in
  CMake and the POSIX audit scripts. `libc/include/limits.h` (`ICD_LIBC_0005`)
  then supplies ISO C17 integer limits and POSIX.1-2024 limits (`PATH_MAX`,
  `NAME_MAX`, `OPEN_MAX`, `PIPE_BUF`, `ARG_MAX`, `SSIZE_MAX`).
- Add standalone `<ctype.h>`, `<assert.h>`, `<inttypes.h>`, and `<strings.h>`
  (`strcasecmp`, `strncasecmp`) under `ICD_LIBC_0005`, keeping XSI-only `ffs`
  absent while `_XOPEN_UNIX` is inactive.
- Extend `struct __microkernel_file` in `libc/src/stdio.c` (`COMP_LIBC_0004`)
  with a 512-byte inline buffer, read/write mode flags, `ungetc` pushback,
  `setvbuf`, and a mutex-guarded open-stream list for `fflush(NULL)` and
  `exit()`. Keep `stdin`, `stdout`, and `stderr` unbuffered by default so serial
  and TTY operations remain immediate.
- Implement copy-on-first-mutate `environ` ownership in `libc/src/stdlib.c` for
  `setenv` and `unsetenv`, paired with base-0/overflow-checked `strto*` parsers
  and `abs`/`labs`/`llabs`.
- Implement async-signal-safe `execv` and stack-buffered `execvp` (`PATH`
  default `"/boot:/bin"`) in `libc/src/unistd.c`, and teach `find_bootfs_image`
  in `kernel/core/proc.c` to strip leading `"/boot/"` prefixes.

## Rejected alternatives

- Keeping `<limits.h>` behind Clang's resource directory (fails to expose
  `PATH_MAX` and `PIPE_BUF` under `-ffreestanding` where `__STDC_HOSTED__` is
  `0`).
- Mutating the kernel-built `envp` stack array in place (cannot grow or safely
  free entries across repeated `setenv`/`unsetenv` calls).

## Consequences

- Portable C17 and POSIX applications (including the upcoming Ring 3 `sh` and
  core utilities) can use buffered `FILE` I/O, `setenv`/`unsetenv`, `execvp`,
  `<ctype.h>`, `<assert.h>`, `<inttypes.h>`, `<strings.h>`, `<limits.h>`,
  `strdup`, `strstr`, and `strerror`.
- Verified by `stdiotest` (`VER_LIBC_0006`) and all four POSIX CTest gates.
```
