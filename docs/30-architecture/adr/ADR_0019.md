# ADR_0019 — Buffered Stdio, Environment Changes, execvp, and Core C17 Headers

```{adr} Buffered stdio, environment changes, execvp, and core C17 headers
:id: ADR_0019
:status: accepted

## Context

For `SWR_LIBC_0007`, the system must give buffered `<stdio.h>` streams, `setenv`
and `unsetenv`, `execv` and `execvp`, and core C17 and POSIX headers
(`<ctype.h>`, `<assert.h>`, `<inttypes.h>`, `<strings.h>`, `<limits.h>`). Before
this decision, `<stdio.h>` operated only on unbuffered `stdout` and `stderr`
writes, and `<limits.h>` came only from Clang freestanding headers without POSIX
limits.

## Decision

- CMake and the POSIX check scripts put `${SYSROOT_DIR}/usr/include` before
  `${CLANG_RESOURCE_DIR}/include`. `libc/include/limits.h` (`ICD_LIBC_0005`)
  then gives ISO C17 integer limits and POSIX.1-2024 limits (`PATH_MAX`,
  `NAME_MAX`, `OPEN_MAX`, `PIPE_BUF`, `ARG_MAX`, `SSIZE_MAX`).
- The project adds standalone `<ctype.h>`, `<assert.h>`, `<inttypes.h>`, and
  `<strings.h>` (`strcasecmp`, `strncasecmp`) in `ICD_LIBC_0005`. XSI-only `ffs`
  stays missing while `_XOPEN_UNIX` is not active.
- `struct __microkernel_file` in `libc/src/stdio.c` (`COMP_LIBC_0004`) adds a
  512-byte inline buffer, read and write flags, `ungetc`, `setvbuf`, and a
  mutex-locked open-stream table for `fflush(NULL)` and `exit()`. `stdin`,
  `stdout`, and `stderr` stay unbuffered initially. Thus serial and TTY output
  goes out immediately.
- `libc/src/stdlib.c` adds copy-on-first-change `environ` ownership for `setenv`
  and `unsetenv`, base-0 `strto*` parsers with overflow checks, and `abs`,
  `labs`, and `llabs`.
- `libc/src/unistd.c` adds async-signal-safe `execv` and stack-buffered `execvp`
  (`PATH` `"/boot:/bin"`). `find_bootfs_image` in `kernel/core/proc.c` removes
  initial `"/boot/"` prefixes.

## Rejected alternatives

- `<limits.h>` after Clang freestanding headers, which hides `PATH_MAX` and
  `PIPE_BUF` with `-ffreestanding` when `__STDC_HOSTED__` is `0`.
- Changes to the kernel `envp` stack array in its initial memory, which cannot
  expand or release entries across more than one `setenv` or `unsetenv` call.

## Results

- Portable C17 and POSIX executables (such as Ring 3 `sh` and core utilities)
  can use buffered `FILE` I/O, `setenv`, `unsetenv`, `execvp`, `<ctype.h>`,
  `<assert.h>`, `<inttypes.h>`, `<strings.h>`, `<limits.h>`, `strdup`, `strstr`,
  and `strerror`.
- `stdiotest` (`VER_LIBC_0006`) and all four POSIX CTest checks do tests for
  these interfaces.
```
