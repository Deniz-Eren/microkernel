# ADR_0014 — Kernel SYS_GETENTROPY Mixer and Issue 8 C17 Library Extensions

```{adr} Kernel SYS_GETENTROPY mixer and Issue 8 C17 library extensions
:id: ADR_0014
:status: accepted

## Context

For `SWR_LIBC_0005`, the system must give POSIX.1-2024 Base `strlcpy`,
`strlcat`, `reallocarray`, `getentropy`, and `secure_getenv`, with C11 and C17
`<stdatomic.h>`, `<stdalign.h>`, and `<uchar.h>`. Clang gives freestanding
`<stdatomic.h>` and `<stdalign.h>`, but `<uchar.h>` and kernel entropy were
missing.

## Decision

- `kernel/core/entropy.c` adds `SYS_GETENTROPY` (`48`). It mixes CPUID `RDRAND`,
  `RDTSC`, `CLOCK_MONOTONIC` ticks, and caller `pid` and `tid` in a lock-free
  `xoshiro256**` state. It rejects lengths more than `GETENTROPY_MAX` (`256`)
  with `-EINVAL`.
- `libc/src/string.c` adds `strlcpy` and `strlcat`. `libc/src/stdlib.c` adds
  thread-safe `realloc` and `reallocarray` with byte-count headers, `_Exit`,
  `getenv`, and `AT_SECURE` `secure_getenv`.
- `libc/include/uchar.h` and `libc/src/uchar.c` add UTF-8 to UTF-16 and UTF-32
  conversion (`mbrtoc16`, `c16rtomb`, `mbrtoc32`, `c32rtomb`) with
  surrogate-pair and `EILSEQ` checks.
- `posix.headers` does standalone checks of `<stdatomic.h>`, `<stdalign.h>`, and
  `<uchar.h>`, and QEMU `tests/libctest/test_libc_issue8.c` does runtime tests.

## Rejected alternatives

- User-space `RDTSC` only for `getentropy` without a kernel entropy mixer.
- `malloc` blocks without a byte-count header, which prevents safe
  `reallocarray` data writes.

## Results

- `libctest` does tests of `strlcpy`, `strlcat`, `reallocarray`,
  `secure_getenv`, `getentropy`, `<stdatomic.h>`, `<stdalign.h>`, and
  `<uchar.h>` in headless QEMU.
- `SWR_LIBC_0005` is active, and `posix.headers` and `posix.async_signal_safe`
  do checks on it.
```
