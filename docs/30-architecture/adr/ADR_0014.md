# ADR_0014 — Kernel SYS_GETENTROPY Mixer and Issue 8 C17 Library Extensions

```{adr} Kernel SYS_GETENTROPY mixer and Issue 8 C17 library extensions
:id: ADR_0014
:status: accepted

## Context

`SWR_LIBC_0005` requires POSIX.1-2024 Base `strlcpy`, `strlcat`, `reallocarray`,
`getentropy`, and `secure_getenv`, plus C11/C17 `<stdatomic.h>`, `<stdalign.h>`,
and `<uchar.h>`. Clang provides freestanding `<stdatomic.h>` and `<stdalign.h>`,
while `<uchar.h>` and kernel entropy were missing.

## Decision

- Add `SYS_GETENTROPY` (`48`) in `kernel/core/entropy.c`. Mix CPUID-detected
  `RDRAND`, `RDTSC`, `CLOCK_MONOTONIC` ticks, and caller `pid`/`tid` through a
  non-blocking `xoshiro256**` state, rejecting lengths over `GETENTROPY_MAX`
  (`256`) with `-EINVAL`.
- Add `strlcpy` and `strlcat` in `libc/src/string.c`, thread-safe size-tagged
  `realloc`/`reallocarray`, `_Exit`, `getenv`, and `AT_SECURE`-aware
  `secure_getenv` in `libc/src/stdlib.c`.
- Implement UTF-8 to UTF-16/UTF-32 conversion (`mbrtoc16`, `c16rtomb`,
  `mbrtoc32`, `c32rtomb`) with surrogate-pair and `EILSEQ` checks in
  `libc/include/uchar.h` and `libc/src/uchar.c`.
- Verify `<stdatomic.h>`, `<stdalign.h>`, and `<uchar.h>` standalone in
  `posix.headers` and at runtime in QEMU `tests/libctest/test_libc_issue8.c`.

## Rejected alternatives

- Deriving `getentropy` only from user-space `RDTSC` without kernel mixing.
- Leaving `malloc` without a size header (blocks safe `reallocarray` copies).

## Consequences

- `libctest` verifies `strlcpy`, `strlcat`, overflow-checked `reallocarray`,
  `secure_getenv`, `getentropy`, `<stdatomic.h>`, `<stdalign.h>`, and
  `<uchar.h>` in headless QEMU.
- `SWR_LIBC_0005` is active and checked by `posix.headers` and
  `posix.async_signal_safe`.
```
