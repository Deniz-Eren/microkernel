# ADR_0008 — IOAPIC IRQ Pulses, CAP_SYS_INTR IOPL, and Scatter-Gather MsgV IPC

```{adr} IOAPIC IRQ pulses, CAP_SYS_INTR IOPL, and scatter-gather MsgV IPC
:id: ADR_0008
:status: accepted

## Context

Milestone 6 (`SWR_IPC_0006`) moves hardware device drivers into isolated Ring 3
servers. Hardware IRQs must reach Ring 3 as IPC pulses with no heap allocation
in interrupt context. Port I/O must use capability checks, and drivers need
scatter-gather IPC verified on QEMU `q35` with no extra flags.

## Decision

- Map the IOAPIC at `0xFEC00000` in `kernel/core/intr.c` and mask all 24 lines
  at boot. Keep one static `chan_msg_t` pulse node per IRQ (`is_static = 1`).
  `intr_dispatch_irq()` masks the line, sends EOI, and queues the pulse with no
  `kmalloc()` or `kfree()`.
- Gate `AttachIntrEvent`, `IntrUnmask`, and `IOPLSet(3)` with `CAP_SYS_INTR` on
  `pcb_t.caps` (granted only to `sysproc` and `rtcdrv` in `proc_spawn_init()`),
  store `tcb_t.iopl`, and preserve IOPL bits across signal delivery.
- Implement `ipc_msg_readv` and `ipc_msg_writev` (up to `IPC_IOV_MAX = 16`
  segments) with `reply_written` tracking so servers populate scatter-gather
  replies via `WriteMsgV` and complete with `ReplyMsg(msgid, NULL, 0)`.
- Ship a Ring 3 MC146818 CMOS RTC driver (`servers/rtcdrv`, `/dev/rtc`) using
  ports `0x70`/`0x71` and IOAPIC IRQ 8, tested by unprivileged `tests/drvtest`.

## Rejected alternatives

- Allocating IRQ pulse nodes with `kmalloc()` inside the interrupt handler.
- Using COM2 (`0x2F8`) loopback, which needs extra `-serial` flags in QEMU.

## Consequences

- Hardware IRQ delivery, `-EPERM` port I/O enforcement, and scatter-gather
  `ReadMsgV`/`WriteMsgV` pass end-to-end in headless QEMU alongside Milestones 1
  to 5.
```
