# ADR_0008 — IOAPIC IRQ Pulses, CAP_SYS_INTR IOPL, and Vectored MsgV IPC

```{adr} IOAPIC IRQ pulses, CAP_SYS_INTR IOPL, and vectored MsgV IPC
:id: ADR_0008
:status: accepted

## Context

Milestone 6 (`SWR_IPC_0006`) moves hardware device drivers to isolated Ring 3
servers. Hardware IRQs must go to Ring 3 as IPC pulses with no heap allocation
in interrupt context. Port I/O must do permission checks, and drivers must use
vectored IPC. QEMU `q35` tests must operate with no more flags.

## Decision

- `kernel/core/intr.c` maps the IOAPIC at `0xFEC00000` and blocks all 24 lines
  at boot. It keeps one static `chan_msg_t` pulse node for each IRQ (`is_static
  = 1`). `intr_dispatch_irq()` blocks the line, sends EOI, and queues the pulse
  without `kmalloc()` or `kfree()`.
- The kernel puts `AttachIntrEvent`, `IntrUnmask`, and `IOPLSet(3)` behind
  `CAP_SYS_INTR` on `pcb_t.caps` (given only to `sysproc` and `rtcdrv` in
  `proc_spawn_init()`). It keeps `tcb_t.iopl` and keeps IOPL bits across
  signals.
- `ipc_msg_readv` and `ipc_msg_writev` move up to `IPC_IOV_MAX = 16` segments
  and keep `reply_written` counts. Servers write vectored replies through
  `WriteMsgV` and complete them with `ReplyMsg(msgid, NULL, 0)`.
- The project includes a Ring 3 MC146818 CMOS RTC driver (`servers/rtcdrv`,
  `/dev/rtc`) on ports `0x70` and `0x71` with IOAPIC IRQ 8. Unprivileged
  `tests/drvtest` does tests of this driver.

## Rejected alternatives

- Heap allocation of IRQ pulse nodes with `kmalloc()` in the interrupt handler.
- COM2 (`0x2F8`) loopback, which must have more `-serial` flags in QEMU.

## Results

- Hardware IRQ pulses, `-EPERM` port I/O checks, and vectored `ReadMsgV` and
  `WriteMsgV` tests complete without errors in headless QEMU with Milestones 1
  to 5.
```
