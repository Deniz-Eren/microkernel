# ADR_0060 — Terminal runtime for full-screen editors and multiplexers

```{adr} Terminal runtime for full-screen editors and multiplexers
:id: ADR_0060
:status: accepted

Run Vim, tmux, and Neovim in Ring 3 over the existing PTY and socket services.
Harden the ttyserv line discipline for raw-mode timing and flow control. Add
`fsync`, `wcwidth`, and `wcswidth` to `libc`. Ship a `terminfo` database in the
sysroot. Build the three tools as out-of-tree CMake ports and use PUC Lua 5.1
for Neovim.
```

## Context

Vim, tmux, and Neovim are full-screen terminal applications. They rely on
raw-mode reads with short timeouts, `ISIG` and `OPOST` handling, window-size
changes, and PTY file-descriptor passing.

The current `ttyserv` line discipline reads raw-mode bytes but does not enforce
`VTIME`. It does not implement `IXON`, `IXOFF`, or `OXTABS`. The C library has
no `fsync`, `wcwidth`, or `wcswidth`. There is no `terminfo` database in the
sysroot.

The kernel rejects `WRITE|EXEC` page protection in `sys_vm_protect`. That rule
blocks a LuaJIT build of Neovim that writes and executes the same page.

## Decision

1. **Harden the line discipline in ttyserv:** The line discipline enforces
   `VTIME` in raw-mode reads so a standalone `Esc` returns within the configured
   timeout. It implements `IXON`, `IXOFF`, and `OXTABS`. It verifies `ISIG`,
   `OPOST`, `ICRNL`, and `ONLCR` in raw and cbreak modes.
2. **Keep the terminal in Ring 3:** No kernel syscall is added. The microkernel
   boundary stays strict ({need}`ADR_0002`).
3. **Use PTY `SCM_RIGHTS` for tmux attach and detach:** The kernel FD dup shares
   the same `tty_dev_t`. Thus, `termios`, window size, hangup state, and
   controlling-terminal rules carry across address spaces. No new syscall is
   needed.
4. **Build Neovim with PUC Lua 5.1:** Avoid LuaJIT. The kernel W^X rule rejects
   `WRITE|EXEC`, so a JIT that writes then executes the same page fails. PUC Lua
   5.1 has no JIT and avoids the conflict.
5. **Ship a `terminfo` database in the sysroot:** Add `xterm`, `xterm-256color`,
   `tmux-256color`, and `screen-256color`. OpenSSH propagates `$TERM` to the
   session. tmux sets `TERM` to `tmux-256color` for panes.
6. **Build Vim, tmux, and Neovim as Group A CMake ports:** They have complex
   grammar or runtime logic. CMake downloads them and links them to `libc.so`
   and `ncurses` ({need}`WDR_0012`, {need}`BDR_0004`).

## Rejected alternatives

- **Implement the three tools natively:** This duplicates mature upstream tools
  and adds long-term maintenance work.
- **Build Neovim with LuaJIT:** The JIT writes and executes code. The kernel W^X
  rule rejects the combined `WRITE|EXEC` protection, so LuaJIT needs a kernel
  change.
- **Add a kernel PTY or W^X exception syscall:** This breaks the microkernel
  boundary for a user-space tooling concern.

## Results

- The ttyserv line discipline supports raw-mode timing and flow control.
- `libc` provides `fsync`, `wcwidth`, and `wcswidth` for full-screen editors.
- The sysroot carries a `terminfo` database and propagates `$TERM` over SSH.
- Vim, tmux, and Neovim run in Ring 3 over the existing PTY and socket services.
