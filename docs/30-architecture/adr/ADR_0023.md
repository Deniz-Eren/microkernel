# ADR_0023 — Select Over Multi-Server ppoll and Kernel Leak Reclamation

```{adr} Select over multi-server ppoll and kernel leak reclamation
:id: ADR_0023
:status: accepted

Build `<sys/select.h>` (`select`, `pselect`, `fd_set`, `FD_*`) as a Ring 3
translation layer over multi-server `ppoll()`. Reclaim zombie process and thread
allocations in Ring 0, and add lightweight `SYS_SYS_STATS` and server stats RPCs
to verify zero resource leaks in QEMU.
```

## Context

`SWR_DOCS_0004` requires `<sys/select.h>` (`select`, `pselect`) across all Ring
3 descriptor servers and quantitative proof of zero PMM frame, descriptor, and
server handle leaks under cross-subsystem stress. Auditing the kernel during
`TSK_0020` showed that `sys_proc_wait()` released user page tables but left
`pcb_t`, `conn_table`, and thread blocks on `kheap`. Long-lived processes also
did not reclaim zombie thread stacks on exit.

## Decision

- Declare `<sys/select.h>` (`FD_SETSIZE = 64`, `struct timeval`, `fd_set`,
  `FD_CLR`, `FD_ISSET`, `FD_SET`, `FD_ZERO`, `select`, `pselect`) with zero
  `<sys/microkernel.h>` leakage (`ICD_IPC_0014`). Implement both functions and
  macros in `libc/src/select.c` (`COMP_IPC_0014`) over multi-server `ppoll()`
  with `__libc_cancel_point()` hooks and `POLLNVAL` to `EBADF` translation.
- Reclaim zombie thread user stacks, kernel stacks, FPU buffers, and `tcb_t`
  entries in `proc_reap_zombie_threads()` and reuse unmapped stack slots in
  `proc_user_stack_alloc()`. Reclaim `pcb_t`, `conn_table`, and threads in
  `proc_reap_zombie()` during `sys_proc_wait()`.
- Add `SYS_SYS_STATS` (`52`, `SysStats()` in `<sys/vm.h>`) plus `PIPE_OP_STATS`,
  `VFS_OP_STATS`, and `SOCK_OP_STATS` RPCs so `tests/stresstest/test_stress.c`
  (`VER_DOCS_0005`) verifies exact before/after PMM and handle equality.

## Rejected alternatives

- Adding a dedicated kernel `SYS_SELECT` syscall, which duplicates Ring 3
  descriptor state in Ring 0.
- Checking leaks only by absence of crashes instead of exact frame and handle
  counters.

## Consequences

- `select()` and `pselect()` share multi-server readiness and signal-mask logic
  with `ppoll()` while passing Gate 1, Gate 2, and Gate 3b cancellation checks.
- Long-running processes and repeated `fork`/`execvp`/`pthread_create` workloads
  operate with zero PMM frame or handle growth.
