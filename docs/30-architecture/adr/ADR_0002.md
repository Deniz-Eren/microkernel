# ADR_0002 — Isolated Ring 0 Kernel and Ring 3 User Services

```{adr} Isolated Ring 0 kernel and Ring 3 user services
:id: ADR_0002
:status: accepted

## Context

The microkernel must isolate Ring 0 hardware mechanisms from higher-level
services. Name registries, drivers, and user executables must operate in Ring 3.

## Decision

Only the core kernel operates in Ring 0 at `0xFFFFFFFF80000000` with SMAP, SMEP,
and W^X page tables. All servers (`sysproc`, `ipcserv`) and user executables
operate in Ring 3 in isolated PML4 address spaces. Ring 3 servers send messages
through `syscall` and synchronous IPC channels.

## Rejected alternatives

- One shared address space for system servers and the kernel.
- Kernel access to user pointers as an alternative to HHDM memory access.

## Results

- Each address-space copy does a check of mapped page entries and write
  permissions.
- Developers can change, start again, and do tests of user servers independently
  of Ring 0.
```
