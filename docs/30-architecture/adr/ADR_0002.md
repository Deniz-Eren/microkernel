# ADR_0002 — Separate Minimal Ring 0 Kernel from Ring 3 User Services

```{adr} Separate minimal Ring 0 kernel from Ring 3 user services
:id: ADR_0002
:status: accepted

## Context

The microkernel must enforce strict privilege isolation between core hardware
and scheduling mechanisms and higher-level operating system services such as the
name registry, device drivers, and user applications.

## Decision

Execute only the core kernel in Ring 0 at `0xFFFFFFFF80000000` with SMAP, SMEP,
and W^X page tables. Execute all servers (`sysproc`, `ipcserv`) and applications
in Ring 3 with per-process PML4 address spaces, communicating via `syscall` and
synchronous IPC channels.

## Rejected alternatives

- Sharing a single address space across system servers and the kernel.
- Allowing direct kernel dereference of user pointers instead of HHDM copies.

## Consequences

- Every cross-space copy validates page-table presence and write permissions.
- User servers can be developed, tested, and restarted independently of Ring 0.
```
