# ADR_0022 — ACPI MADT/SPCR Tables, Parameterized Drivers, and Interactive sh

```{adr} ACPI MADT/SPCR tables, parameterized drivers, and interactive sh
:id: ADR_0022
:status: accepted

## Context

For `SWR_BOOT_0003`, the kernel must parse ACPI `MADT` and `SPCR` hardware
tables. With these tables, the kernel and Ring 3 drivers do not use hardcoded
ISA IOAPIC, UART, and RTC addresses. Ring 3 `ttyserv` must also control user
`stdout` and `stderr` TX (`OPOST` and `ONLCR`) and local `ECHO`. Users can then
boot into interactive `/boot/sh` in QEMU.

## Decision

- `kernel/include/kernel/acpi.h` and `kernel/core/acpi.c` (`COMP_BOOT_0003`)
  find RSDP and do checksum checks on RSDT and XSDT. They parse `MADT` IOAPIC
  bases, Interrupt Source Overrides (ISOs), and `SPCR` (with COM1 `0x3F8` and
  ISO-mapped IRQ 4 as an alternative).
- `kernel/core/intr.c` maps the IOAPIC physical base from `MADT` and applies ISO
  polarity and edge or level mode flags on redirection entries.
- `libc/include/sys/bootinfo.h` expands `boot_info_t`, and `spawn_image_argv()`
  in `kernel/core/proc.c` gives `-p` and `-i` arguments to `ttyserv` and
  `rtcdrv`.
- `servers/ttyserv/main.c` writes to the configured 16550A UART with `OPOST` and
  `ONLCR` newline translation and `ECHO`/`ECHOE` keystroke echo on COM1 RX
  interrupts. `libc/src/tty.c` sends user `FD_KIND_CONSOLE` and `FD_KIND_TTY`
  writes through `/dev/tty`. It uses `SYS_DEBUG_LOG` as an alternative for
  `sysproc`, `ttyserv`, and initial boot before `/dev/tty` starts.
- `kernel/core/proc.c` adds Multiboot2 `init=sh` interactive boot mode.
  `./scripts/env.sh run` starts Podman and QEMU with `-serial mon:stdio` to boot
  into `/boot/sh`.

## Rejected alternatives

- Hardcoded `0xFEC00000`, `0x3F8`, IRQ 4, and IRQ 8 constants in Ring 0 and Ring
  3 drivers.
- `sysproc` or `ttyserv` writes through `/dev/tty`, which cause self-IPC
  deadlock.

## Results

- `VER_BOOT_0002` does tests of ACPI `MADT` tables, parameterized `ttyserv` and
  `rtcdrv`, and Ring 3 `OPOST` TX in headless QEMU.
- Users can start an interactive Microkernel shell session with
  `./scripts/env.sh run`.
```
