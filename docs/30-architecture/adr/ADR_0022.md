# ADR_0022 — ACPI MADT/SPCR Discovery, Parameterized Drivers, and Interactive sh

```{adr} ACPI MADT/SPCR discovery, parameterized drivers, and interactive sh
:id: ADR_0022
:status: accepted

## Context

`SWR_BOOT_0003` requires ACPI `MADT` and `SPCR` hardware discovery so the kernel
and Ring 3 drivers avoid hardcoded ISA IOAPIC, UART, and RTC addresses. It also
requires Ring 3 `ttyserv` to own user `stdout`/`stderr` TX (`OPOST`/`ONLCR`) and
local `ECHO` so users can boot interactively into `/boot/sh` under QEMU.

## Decision

- Add `kernel/include/kernel/acpi.h` and `kernel/core/acpi.c` (`COMP_BOOT_0003`)
  to locate RSDP and validate RSDT/XSDT checksums. Parse `MADT` IOAPIC bases and
  Interrupt Source Overrides (ISOs), plus `SPCR` when present (falling back to
  COM1 `0x3F8` and ISO-mapped IRQ 4).
- Update `kernel/core/intr.c` to map the `MADT`-discovered IOAPIC physical base
  and apply ISO polarity and trigger-mode flags on redirection entries.
- Extend `boot_info_t` in `libc/include/sys/bootinfo.h` and add
  `spawn_image_argv()` in `kernel/core/proc.c` to pass discovered `-p`/`-i`
  arguments to `ttyserv` and `rtcdrv`.
- Update `servers/ttyserv/main.c` to transmit directly to the configured 16550A
  UART with `OPOST`/`ONLCR` newline translation and `ECHO`/`ECHOE` keystroke
  echo on COM1 RX interrupts. Route user `FD_KIND_CONSOLE`/`FD_KIND_TTY` writes
  through `/dev/tty` in `libc/src/tty.c` with safe `SYS_DEBUG_LOG` fallback for
  PID 1 (`sysproc`), `ttyserv` itself, and early boot before `/dev/tty` starts.
- Add Multiboot2 `init=sh` interactive boot mode in `kernel/core/proc.c` and
  `./scripts/env.sh run` (interactive Podman + QEMU `-serial mon:stdio`) so
  users can boot straight into `/boot/sh`.

## Rejected alternatives

- Keeping hardcoded `0xFEC00000`, `0x3F8`, IRQ 4, and IRQ 8 constants across
  Ring 0 and Ring 3 drivers.
- Routing `sysproc` or `ttyserv` writes through `/dev/tty` (causes self-IPC
  deadlock).

## Consequences

- ACPI `MADT` discovery, parameterized `ttyserv`/`rtcdrv`, and Ring 3 `OPOST` TX
  are verified in headless QEMU (`VER_BOOT_0002`).
- Users can launch an interactive Microkernel shell session with
  `./scripts/env.sh run`.
```
