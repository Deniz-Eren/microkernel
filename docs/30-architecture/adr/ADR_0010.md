# ADR_0010 — Thread FS.base TLS and Small SYS_FUTEX Kernel ABI

```{adr} Thread FS.base TLS and small SYS_FUTEX kernel ABI
:id: ADR_0010
:status: accepted
:supersedes: ADR_0005

## Context

For `SWR_PROC_0005`, the system must give POSIX.1-2024 Base `<pthread.h>`,
`<semaphore.h>`, and hardware thread-local storage. Mutexes, `pthread_cond_t`,
barriers, rwlocks, and semaphores in Ring 0 make the microkernel larger.

## Decision

- The kernel adds three small syscalls (`39` through `41`):
  `SYS_THREAD_SET_FSBASE` (writes `IA32_FS_BASE` and keeps `tcb_t.fs_base`),
  `SYS_THREAD_EXIT`, and `SYS_FUTEX` (`FUTEX_WAIT` with optional
  `CLOCK_MONOTONIC` or `CLOCK_REALTIME` time limit, and `FUTEX_WAKE`).
- The kernel initializes `tcb_t.fs_base` to the 0-filled user stack base. As a
  result, `%fs:0` does not fault in `ThreadSpawn` threads. `__errno_location()`
  uses O(1) `%fs:0` TLS and keeps the lock-free TID table from `ADR_0005` as an
  alternative.
- `libc/src/pthread.c` and `libc/src/semaphore.c` give all `<pthread.h>` and
  `<semaphore.h>` operations in Ring 3 with `memory_order_acquire` and
  `memory_order_release` atomics and `SYS_FUTEX`. `sem_post` stays
  async-signal-safe.

## Rejected alternatives

- Kernel syscalls for mutexes, `pthread_cond_t`, barriers, and semaphores.
- Only the TID-table `errno`, which calls a syscall on each `errno` access.

## Results

- `pthreadtest` does tests of `FS.base` TLS, mutexes, `pthread_cond_clockwait`,
  barriers, spinlocks, rwlocks, `pthread_key_t`, and `sem_*` in QEMU.
- `SWR_PROC_0005` is active, and QEMU, `posix.headers`, and
  `posix.async_signal_safe` do tests for it.
```
