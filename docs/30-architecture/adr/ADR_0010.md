# ADR_0010 — Per-Thread FS.base TLS and Minimal SYS_FUTEX Kernel ABI

```{adr} Per-thread FS.base TLS and minimal SYS_FUTEX kernel ABI
:id: ADR_0010
:status: accepted
:supersedes: ADR_0005

## Context

`SWR_PROC_0005` requires POSIX.1-2024 Base `<pthread.h>` and `<semaphore.h>`
plus hardware per-thread TLS. Placing mutexes, condvars, barriers, rwlocks, and
semaphores in Ring 0 inflates the microkernel.

## Decision

- Add three minimal syscalls (`39` through `41`): `SYS_THREAD_SET_FSBASE`
  (writes `IA32_FS_BASE` and saves `tcb_t.fs_base`), `SYS_THREAD_EXIT`, and
  `SYS_FUTEX` (`FUTEX_WAIT` with optional `CLOCK_MONOTONIC`/`CLOCK_REALTIME`
  deadline, and `FUTEX_WAKE`).
- Pre-point `tcb_t.fs_base` at the zeroed user stack bottom so `%fs:0` never
  faults in raw `ThreadSpawn` threads. Upgrade `__errno_location()` to O(1)
  `%fs:0` TLS while retaining the lock-free TID table from `ADR_0005` as a
  fallback.
- Implement all `<pthread.h>` and `<semaphore.h>` primitives in Ring 3
  (`libc/src/pthread.c`, `libc/src/semaphore.c`) with acquire/release atomics
  and `SYS_FUTEX`, keeping `sem_post` async-signal-safe.

## Rejected alternatives

- Adding separate kernel syscalls for mutexes, condvars, barriers, and
  semaphores.
- Keeping TID-table `errno` only (requires a syscall on each `errno` access).

## Consequences

- `pthreadtest` verifies `FS.base` TLS, mutexes, `pthread_cond_clockwait`,
  barriers, spinlocks, rwlocks, TSD keys, and `sem_*` in QEMU.
- `SWR_PROC_0005` is active and verified by QEMU, `posix.headers`, and
  `posix.async_signal_safe`.
```
