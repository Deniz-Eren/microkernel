# ADR_0009 — Kernel 1 ms LAPIC Clocks and Static POSIX Timer Pool

```{adr} Kernel 1 ms LAPIC clocks and static POSIX timer pool
:id: ADR_0009
:status: accepted

## Context

For `SWR_PROC_0006`, the system must give POSIX.1-2024 `<time.h>` clocks and
timers (`CLOCK_MONOTONIC`, `CLOCK_REALTIME`, `clock_nanosleep`, and `timer_*`).
Timer expiry operates in the 1 ms LAPIC interrupt handler, which cannot allocate
kernel heap memory.

## Decision

- `kernel/core/time.c` keeps a 1 ms monotonic nanosecond counter (`g_mono_ns`)
  and a signed realtime offset (`g_realtime_offset_ns`). `apic_irq_dispatch()`
  increases them on each LAPIC tick.
- The scheduler adds `THREAD_SLEEP_BLOCKED` for `clock_nanosleep` (relative and
  `TIMER_ABSTIME`) with `-EINTR` wakeup and remaining-time copy on signal
  arrival.
- The kernel keeps process POSIX timers in a static 64-slot pool (`g_timers`)
  and removes them on process exit (`time_cleanup_proc()`). It queues timer
  signals through `signal_post_to_proc()` and does not call `schedule()` in
  `time_tick()`.
- The project adds syscalls `30` through `38` and `<time.h>` wrappers in
  `libc/src/time.c`. `clock_gettime` and `timer_*` stay async-signal-safe.

## Rejected alternatives

- Heap allocation of timer nodes with `kmalloc()`, which adds heap work and
  cleanup risk.
- Busy loops on `CLOCK_MONOTONIC` in Ring 3 for `nanosleep`, which waste CPU
  time slices.

## Results

- `timetest` does tests of `CLOCK_MONOTONIC`, `CLOCK_REALTIME`,
  `clock_nanosleep`, and periodic `timer_create` and `timer_settime` `SIGUSR1`
  ticks in QEMU.
- `SWR_PROC_0006` is active, and QEMU, `posix.headers`, and
  `posix.async_signal_safe` do tests for it.
```
