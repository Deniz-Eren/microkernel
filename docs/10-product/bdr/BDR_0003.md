# BDR_0003 — Target POSIX.1-2024 (Issue 8) Base Conformance

```{bdr} Target POSIX.1-2024 (Issue 8) Base conformance
:id: BDR_0003
:status: accepted
:drives: SYS_LIBC_0001
:governs: ADR_0003

## Context

User programs, system servers, and future shell utilities need a standard C and
operating system interface rather than an ad-hoc API that blocks portability and
conformance testing.

## Decision

Align the user-space C library, public headers, error numbers, signals, threads,
memory mapping, IPC, and future shell/utilities to IEEE Std 1003.1-2024 (The
Open Group Base Specifications Issue 8, `_POSIX_VERSION=202405L`,
`_POSIX2_VERSION=202405L`) over successive milestones. Keep optional feature
groups (`SHM`, `SPN`, `ML`, `MLR`, `MSG`, `PS`, `XSI`) explicitly gated behind
their standard feature macros.

## Rejected alternatives

- Defining a permanent custom-only C runtime API with no standard baseline.
- Targeting older POSIX Issue 6 or Issue 7 subsets instead of Issue 8.

## Consequences

- `libc` headers and interfaces follow Issue 8 namespace, `errno`,
  async-signal-safety, and cancellation rules as each subsystem matures.
- Mandatory Issue 8 Base groups (`pthread_*`, `sem_*`, monotonic clocks/timers,
  `mmap`/`mprotect`/`msync`/`munmap`, `aio_*`) are exposed without option gates.
- Automated header, symbol, call-graph, and runtime suites can verify
  conformance continuously.
```
