# BDR_0003 — Target POSIX.1-2024 (Issue 8) Base Compatibility

```{bdr} Target POSIX.1-2024 (Issue 8) Base compatibility
:id: BDR_0003
:status: accepted
:drives: SYS_LIBC_0001
:governs: ADR_0003

## Context

User executables, system servers, and shell utilities must have a standard C and
operating system interface. A custom API prevents portability and automatic
compatibility tests.

## Decision

Target compatibility with interfaces from POSIX.1-2024 (IEEE Std 1003.1-2024 /
ISO/IEC/IEEE 9945:2026, `_POSIX_VERSION=202405L`, `_POSIX2_VERSION=202405L`)
across `libc`, headers, error numbers, signals, threads, memory mapping, IPC,
and shell utilities. Keep optional option groups (`SHM`, `SPN`, `ML`, `MLR`,
`MSG`, `PS`, `XSI`) behind their standard feature macros.

## Rejected alternatives

- A permanent custom-only C runtime API with no standard baseline.
- Older POSIX editions (for example POSIX.1-2008 or POSIX.1-2017) as an
  alternative to POSIX.1-2024.

## Results

- `libc` headers and interfaces obey Issue 8 namespace, `errno`,
  async-signal-safety, and cancellation rules as each subsystem matures.
- Mandatory Issue 8 Base groups (`pthread_*`, `sem_*`, monotonic clocks and
  timers, `mmap`, `mprotect`, `msync`, `munmap`, `aio_*`) operate without option
  macros.
- Automatic header, symbol, call-graph, and runtime suites examine compatibility
  status on each build.
```
