# BDR_0003 — Work Toward POSIX.1-2024 (Issue 8) Base Compatibility

```{bdr} Work toward POSIX.1-2024 (Issue 8) Base compatibility
:id: BDR_0003
:status: accepted
:drives: SYS_LIBC_0001
:governs: ADR_0003

## Context

User programs, system servers, and shell utilities need a standard C and
operating system interface. An ad-hoc API blocks portability and automated
compatibility testing.

## Decision

Work toward compatibility with interfaces from POSIX.1-2024 (IEEE Std
1003.1-2024 / ISO/IEC/IEEE 9945:2026, `_POSIX_VERSION=202405L`,
`_POSIX2_VERSION=202405L`) across `libc`, headers, error numbers, signals,
threads, memory mapping, IPC, and shell utilities. Keep optional feature groups
(`SHM`, `SPN`, `ML`, `MLR`, `MSG`, `PS`, `XSI`) behind their standard feature
macros.

## Rejected alternatives

- Defining a permanent custom-only C runtime API with no standard baseline.
- Targeting older POSIX editions (such as POSIX.1-2008 or POSIX.1-2017) instead
  of POSIX.1-2024.

## Consequences

- `libc` headers and interfaces follow Issue 8 namespace, `errno`,
  async-signal-safety, and cancellation rules as each subsystem matures.
- Mandatory Issue 8 Base groups (`pthread_*`, `sem_*`, monotonic clocks/timers,
  `mmap`/`mprotect`/`msync`/`munmap`, `aio_*`) are exposed without option gates.
- Automated header, symbol, call-graph, and runtime suites check compatibility
  progress continuously.
```
