# BDR_0004 — Keep User Space in POSIX.1-2024 and Record Non-POSIX Rules

```{bdr} Keep user space in POSIX.1-2024 and record non-POSIX rules
:id: BDR_0004
:status: accepted
:drives: SYS_LIBC_0001
:governs: ADR_0003

## Context

User-space utilities, headers, and C library interfaces can change when
non-standard OS extensions go into the source tree. Linux or GNU extensions (for
example `/proc`, `nproc`, or non-standard `_SC_*` constants) pull work away from
the POSIX.1-2024 Base target ({need}`BDR_0003`).

## Decision

Keep all public headers, `libc` functions, and `bin/` utilities in POSIX.1-2024
(`IEEE Std 1003.1-2024` / `ISO/IEC/IEEE 9945:2026`). Do not add non-POSIX
user-space interfaces or utilities unless a necessary function is missing from
POSIX.1-2024. Record each non-POSIX user-space rule in a `BDR_` or `ADR_` record
before code work starts.

## Rejected alternatives

- Linux `/proc`, GNU `nproc`, or non-standard `_SC_*` names added with
  POSIX.1-2024 Base work without a formal decision record.
- Unrecorded platform extensions in public POSIX headers.

## Results

- Future milestones target POSIX.1-2024 Base interfaces only (for example `ps`,
  `getconf`, `sysconf`, `confstr`, `pathconf`, and `fpathconf`).
- Internal microkernel IPC and driver ABIs stay isolated in `<sys/...>` and do
  not go into POSIX.1-2024 headers ({need}`ADR_0003`).
- Each future non-POSIX user-space function must have an accepted `BDR_` or
  `ADR_` record that tells why POSIX.1-2024 is not sufficient.
```
