# BDR_0004 — Restrict User Space to POSIX.1-2024 and Record Exceptions

```{bdr} Restrict user space to POSIX.1-2024 and record exceptions
:id: BDR_0004
:status: accepted
:drives: SYS_LIBC_0001
:governs: ADR_0003

## Context

User-space utilities, headers, and C library interfaces can drift when
non-standard OS conventions enter the tree early. Linux or GNU extensions such
as `/proc`, `nproc`, or non-standard `_SC_*` constants dilute focus away from
the POSIX.1-2024 Base target ({need}`BDR_0003`).

## Decision

Keep all public headers, `libc` functions, and `bin/` utilities within
POSIX.1-2024 (`IEEE Std 1003.1-2024` / `ISO/IEC/IEEE 9945:2026`). Do not add
non-POSIX user-space interfaces or utilities unless a needed capability does not
exist in POSIX.1-2024. Record every non-POSIX user-space exception explicitly in
a `BDR_` or `ADR_` record before implementation.

## Rejected alternatives

- Adding Linux `/proc`, GNU `nproc`, or non-standard `_SC_*` names alongside
  POSIX.1-2024 Base work without a formal exception record.
- Allowing undocumented platform extensions inside public POSIX headers.

## Consequences

- Future milestones target POSIX.1-2024 Base interfaces only (such as `ps`,
  `getconf`, `sysconf`, `confstr`, `pathconf`, and `fpathconf`).
- Internal microkernel IPC and driver ABIs stay isolated under `<sys/...>` and
  never leak into POSIX.1-2024 headers ({need}`ADR_0003`).
- Any future non-POSIX user-space feature must have an accepted `BDR_` or `ADR_`
  record that explains why POSIX.1-2024 is not sufficient.
```
