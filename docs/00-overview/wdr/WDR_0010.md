# WDR_0010 — Keep Microkernel Ring 0 Boundary with Governance and CTest

```{wdr} Keep microkernel Ring 0 boundary with governance and CTest
:id: WDR_0010
:status: accepted
:governs: ARC_DOCS_0001, ADR_0002

## Context

Before this decision, `AGENTS.md` made POSIX.1-2024 rules, STE rules, and
traceability checks mandatory, but left the Ring 0 / Ring 3 microkernel boundary
implicit. That omission let a previous agent put a named semaphore table
(`SYS_SEM_OP`) and path buffers (`char path[64]`) in Ring 0 as an alternative to
Ring 3.

## Decision

Make Ring 0 smallness a primary mandatory rule in `AGENTS.md` with Plan-step and
Pre-Commit Checklist checks. Record the Ring 0 compared with Ring 3 boundary and
short code-style rule in `CNV_0007`. Make the boundary automatic through CTest
`arch.microkernel_boundary` (`tests/arch/test_microkernel_boundary.py`). That
test compares each `kernel/core/*.c` module, `SYS_*` syscall, and `struct
__k_fd_entry` field against `tests/arch/microkernel_allowlist.json`. It also
makes sure that each cited `ADR_` is in `docs/` with status `accepted`.

## Rejected alternatives

- Human code inspection alone to find Ring 0 bloat after code changes.
- Boundary rules only in `ADR_0002` without a mechanical CTest check or
  `AGENTS.md` pre-commit check.

## Results

- A new syscall, `kernel/core/*.c` file, or FD-slot field causes
  `arch.microkernel_boundary` to stop with an error unless an accepted `ADR_`
  justifies Ring 0 placement.
- Microkernel boundary discipline stays at the same priority as POSIX.1-2024
  compatibility across all future agents and models.
```
