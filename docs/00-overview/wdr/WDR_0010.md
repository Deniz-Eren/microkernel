# WDR_0010 — Enforce Microkernel Ring 0 Boundary via Governance and CTest Gate

```{wdr} Enforce microkernel Ring 0 boundary via governance and CTest gate
:id: WDR_0010
:status: accepted
:governs: ARC_DOCS_0001, ADR_0002

## Context

`AGENTS.md` previously enforced POSIX.1-2024 rules, ASD-STE100 text rules, and
traceability gates, while leaving the Ring 0 / Ring 3 microkernel boundary
implicit. That gap let an earlier agent place a named semaphore table
(`SYS_SEM_OP`) and path buffers (`char path[64]`) inside Ring 0 instead of Ring
3.

## Decision

Elevate Ring 0 minimality to a top-level mandatory rule in `AGENTS.md` with
Predict-phase and Pre-Commit Checklist gates. Codify the Ring 0 vs. Ring 3
boundary and concise code-style rule in `CNV_0007`. Enforce the boundary
mechanically through CTest `arch.microkernel_boundary`
(`tests/arch/test_microkernel_boundary.py`). The test checks every
`kernel/core/*.c` module, `SYS_*` syscall, and `struct __k_fd_entry` field
against `tests/arch/microkernel_allowlist.json`. It also verifies that every
cited `ADR_` exists with status `accepted`.

## Rejected alternatives

- Relying only on human code review to catch Ring 0 bloat after implementation.
- Documenting the boundary only inside `ADR_0002` without a mechanical CTest
  gate or `AGENTS.md` pre-commit checkpoint.

## Consequences

- Adding a syscall, `kernel/core/*.c` file, or FD-slot field fails
  `arch.microkernel_boundary` unless an accepted `ADR_` justifies Ring 0
  placement.
- Microkernel architectural purity stays enforced at the same priority as
  POSIX.1-2024 compatibility across all future agents and models.
```
