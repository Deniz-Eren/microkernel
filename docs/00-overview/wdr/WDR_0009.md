# WDR_0009 — Consolidate Legacy Scaffolding Documents into Sphinx-Needs

```{wdr} Consolidate legacy scaffolding documents into Sphinx-Needs
:id: WDR_0009
:status: accepted
:governs: ARC_DOCS_0001, ADR_0001

## Context

When `ADR_0001` adopted Sphinx-Needs, five pre-existing `agent-scaffolding`
documents (`docs/TASKS.md`, `docs/DECISIONS.md`, `docs/CONVENTIONS.md`,
`docs/VISION.md`, and `docs/ARCHITECTURE.md`) stayed excluded via
`model.code_tag_exclude`. That created two parallel documentation systems that
drifted apart across commits.

## Decision

Port all unique historical milestones, decisions, conventions, vision
principles, and architecture details from those five files into the Sphinx-Needs
model (`docs/records/`, `docs/00-overview/`, `docs/10-product/`, and
`docs/30-architecture/adr/`). Remove the five legacy files and drop them from
`code_tag_exclude` in `.docs-traceability-setup.yml`. Redirect `AGENTS.md`,
`README.md`, and `docs/skills/` to the Sphinx-Needs documents. Retain
`docs/THIRD-PARTY-NOTICES.md` because no traceability document replaces legal
third-party attributions.

## Rejected alternatives

- Keeping both legacy `agent-scaffolding` Markdown files and Sphinx-Needs files
  synchronized by hand on every commit.
- Deleting legacy files without porting `ADR-1` through `ADR-19`, Milestones 1
  to 4, or file-naming conventions.

## Consequences

- The repository maintains one single source of truth for tasks, history,
  roadmap, conventions, vision, context, and decisions (`ADR_`, `BDR_`, `WDR_`).
- All agent workflows and pre-commit checks operate directly on the traceable
  Sphinx-Needs model while preserving `docs/THIRD-PARTY-NOTICES.md`.
```
