# WDR_0002 — Enforce Two-Tier Bidirectional Code and POSIX Traceability

```{wdr} Enforce two-tier bidirectional code and POSIX traceability
:id: WDR_0002
:status: accepted
:governs: ARC_DOCS_0001, ADR_0003

## Context

End-to-end POSIX.1-2024 traceability must link standard clauses to headers,
source modules, and test files. It must avoid per-function Markdown entries
across 86 headers and over 1,100 interfaces.

## Decision

Adopt a two-tier bidirectional traceability method:

- **Tier 1 (Contract-level Sphinx-Needs):** Author `SWR_` requirements at the
  header, behavioral-contract, or subsystem level using the `ste-writing-skill`
  skill with `must` (`authoring.modal_verb: must`) and a structured `:posix:`
  reference field. Keep `ICD_` and `COMP_` scoped per header or feature group.
  Tag public headers with `ICD_`, implementation modules with `COMP_`, and test
  files with `VER_`. Never place `SYS_` or `SWR_` IDs in source code.
- **Bidirectional build gate:** `need_tag_check.py` stops the build (`-W`) if
  any active `ICD_`, `COMP_`, or automated `VER_` item has no `need::` tag. It
  also stops if any `test_*` / `*_test.*` / `check_*` file lacks a `VER_` tag.
  Name new POSIX C test files `test_*.c`.
- **Source-text and language gates:** Every new or changed file must pass
  `.editorconfig` and `docs-traceability-setup` `scripts/check_text.py` (line
  width, greedy prose packing, and Doxygen headers) alongside `clang-format`,
  `clang-tidy`, CTest, and optional `ste-writing-skill` when installed.
- **Tier 2 (Automated manifest symbol gate):** Check symbol-level POSIX.1-2024
  coverage against `issue8-manifest.tsv` (`SWR_DOCS_0003`). Do not write one
  directive per trivial C function.

## Rejected alternatives

- Authoring four Sphinx-Needs directives per individual C library function.
- Checking code tags only in the code-to-docs direction, allowing active `ICD_`,
  `COMP_`, or `VER_` items to exist with no code implementation or test.

## Consequences

- Every active interface, component, and automated test is provably linked to
  source code and reflected in the generated code-trace and POSIX matrices.
- Adding new POSIX functions scales cleanly without Markdown directive bloat.
```
