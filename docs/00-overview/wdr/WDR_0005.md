# WDR_0005 — Keep Podman env.sh Workflow and Unified tests Layout

```{wdr} Keep Podman env.sh workflow and unified tests layout
:id: WDR_0005
:status: accepted
:governs: ARC_DOCS_0001

## Context

The project had an active `Containerfile` and `scripts/env.sh` workflow with
`podman run`. At the same time, the QEMU test harness stayed in `scripts/` and
test executables (`ipccli`, `sigtest`) stayed in `apps/`.

## Decision

Keep `Containerfile` (`microkernel-dev`) and `scripts/env.sh` as the one
container entry point, with `scripts/enter-dev.sh` as a wrapper for `env.sh
shell`. Move all test harnesses, Ring 3 test executables, POSIX suites, and
traceability tests into `tests/` and remove `apps/`.

## Rejected alternatives

- A second Podman Compose entry point (`docker-compose.yml`).
- Ring 3 test executables divided between `apps/` and `scripts/`.

## Results

- `scripts/env.sh` controls configure, build, test, clean, and interactive shell
  steps consistently.
- All automatic tests and test executables stay in `tests/` and go into
  `boot.tar` through `CMakeLists.txt`.
```
