# WDR_0005 — Keep Podman env.sh Workflow and Unified tests Layout

```{wdr} Keep Podman env.sh workflow and unified tests layout
:id: WDR_0005
:status: accepted
:governs: ARC_DOCS_0001

## Context

The project already had a working `Containerfile` and `scripts/env.sh` workflow
using `podman run`. Meanwhile, the QEMU test harness lived in `scripts/` and
test apps (`ipccli`, `sigtest`) lived in `apps/`.

## Decision

Keep `Containerfile` (`microkernel-dev`) and `scripts/env.sh` as the single
container entry point, with `scripts/enter-dev.sh` delegating to `env.sh shell`.
Move all test harnesses, Ring 3 test programs, POSIX suites, and traceability
tests under `tests/` and remove `apps/`.

## Rejected alternatives

- Adding a second Podman Compose entry point (`docker-compose.yml`).
- Keeping Ring 3 test programs split between `apps/` and `scripts/`.

## Consequences

- `scripts/env.sh` drives configure, build, test, clean, and interactive shell
  runs consistently.
- All automated tests and test binaries live under `tests/` and pack into
  `boot.tar` through `CMakeLists.txt`.
```
