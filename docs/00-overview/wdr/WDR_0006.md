# WDR_0006 — Use ste-writing-skill and Modal Verb must

```{wdr} Use ste-writing-skill and modal verb must
:id: WDR_0006
:status: accepted
:governs: ARC_DOCS_0001

## Context

Project documents need clear, consistent technical English. Earlier,
`.docs-traceability-setup.yml` used `authoring.modal_verb: shall`, which did not
match the modal verb `must` used across project requirements.

## Decision

Use the `ste-writing-skill` skill when drafting `README.md` and non-immutable
documents in `docs/` (including Sphinx-Needs `{sys}`, `{swr}`, and specification
directives). Set `authoring.modal_verb: must` in `.docs-traceability-setup.yml`
and keep original project terms in `technical_terms.txt` and
`allowed_phrases.txt`. Never copy any content from `ste-writing-skill` into this
repository. Run `tools/check_ste.py` when `ste-writing-skill` is installed on
the build machine, and skip cleanly when absent.

## Rejected alternatives

- Writing free prose with no technical writing checks.
- Keeping `shall` in requirements and excluding `docs/20-system/` from writing
  checks.
- Failing builds on machines where optional `ste-writing-skill` is absent.

## Consequences

- Governance documents, specifications, and requirements use consistent
  technical writing checked by `tools/check_ste.py` when `ste-writing-skill` is
  installed.
- Writers add new domain terms to `technical_terms.txt` or `allowed_phrases.txt`
  when they add new subsystems.
```
