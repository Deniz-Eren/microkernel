# WDR_0006 — Use STE and Modal Verb must

```{wdr} Use STE and modal verb must
:id: WDR_0006
:status: accepted
:governs: ARC_DOCS_0001

## Context

Project documents must use clear, standard technical English. Before this
decision, `.docs-traceability-setup.yml` used `authoring.modal_verb: shall`.
That option did not agree with the modal verb `must` used across project
requirements.

## Decision

Use `ste-writing-skill` (STE) when you write `README.md` and non-immutable
documents in `docs/` (with Sphinx-Needs `{sys}`, `{swr}`, and specification
directives). Set `authoring.modal_verb: must` in `.docs-traceability-setup.yml`.
Keep project terms in `technical_terms.txt` and `allowed_phrases.txt`. Do not
make a copy of content from `ste-writing-skill` into this repository. Do
`tools/check_ste.py` when `ste-writing-skill` is installed on the build host,
and skip it without error when missing.

## Rejected alternatives

- Free prose with no STE checks.
- Retention of `shall` in requirements without checks on `docs/20-system/`.
- Build errors on hosts where optional `ste-writing-skill` is missing.

## Results

- Governance documents, specifications, and requirements use standard STE
  technical text. `tools/check_ste.py` examines these files when
  `ste-writing-skill` is installed.
- Authors add new domain terms to `technical_terms.txt` or `allowed_phrases.txt`
  when they add new subsystems.
```
